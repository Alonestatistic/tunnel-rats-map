Faction Map API

Read the map from a Discord bot, a server website, an in-game overlay or anything else that can send an HTTP request. Optionally let it add and remove markers.

1. Get a key

  • Server key: made by a server owner or admin in the Server tab. Sees everything marked Whole server.
  • Faction key: made by a faction leader or officer. Also sees that faction's markers and crew notes.
  • Tick Allow it to add / edit / delete markers for a write key. Leave it off for a read-only key.
  • Private markers and private notes are never shown through the API.

The key (it starts with fmk_) is shown once. Keep it secret: anyone with it sees what it sees. Revoke it in the Server tab if it leaks.

2. Calls

Every call is a POST with a JSON body to:

https://YOUR-PROJECT.supabase.co/rest/v1/rpc/<function>

Send these two headers on every call (the public key is the same one the website uses):

apikey: YOUR_PUBLISHABLE_KEY
Content-Type: application/json

api_map: read the map

FieldRequiredMeaning
p_keyyesYour fmk_… key
p_mapnoOnly markers on this map, e.g. "nasdara" or "chernarusplus"
p_notesnotrue to include server notes (and crew notes for faction keys)

Response:

{
  "server":  { "id": "…", "name": "Badlands PvP", "map": "nasdara" },
  "scope":   "faction",
  "faction": { "id": "…", "name": "Wolves", "tag": "WLF", "flag": "Wolf", "color": "#8c8c8c" },
  "factions": [ … every faction on the server … ],
  "features": [
    { "id": "…", "vis": "server", "map": "nasdara", "faction_id": "…", "owner": "someuser",
      "updated_at": "2026-11-16T18:02:11Z",
      "data": { "kind": "marker", "cat": "trader", "name": "Black market", "pos": [9630, 4080], … },
      "notes": [ { "vis": "server", "body": "Open 6pm–2am", "author": "someuser", "created_at": "…" } ] }
  ]
}

api_upsert: add or change a marker (write keys)

FieldRequiredMeaning
p_keyyesWrite key
p_featureyesThe marker (see below). Re-sending the same id updates it.
p_visno"faction" (default, faction keys only) or "server"
p_mapnoMap id. Defaults to the server's map.

Returns the marker id.

api_delete: remove a marker (write keys)

Returns true if something was deleted.

3. Marker format

Coordinates are in-game metres [x, z], the same numbers iZurvive and the map's corner readout show. 0,0 is the bottom-left corner.

FieldMeaning
idAny unique text, 8+ characters (a UUID is ideal)
kindmarker (needs pos), circle (pos + radius), polygon (points, 3+), route (points, 2+)
catbase compound ally enemy territory safezone danger raid trap rp trader vehicle military water medical stash sighting rally poi route
name, notesLabel and description
color, flagHex colour and an armband flag id (e.g. Wolf, Chernarus, NAPA)
parent, numFor compounds: the base's id and the compound number
dExtra details, e.g. vehicles: {"model":"Olga 24","fuel":40,"state":"Needs parts","parts":["Spark plug","Wheels"]}
updated, authorEpoch ms and a display name. Set updated to Date.now() so open maps pick up the change.

4. Minigames and the score sheet

Each server has a score sheet: every player gets a points wallet (starting at 1000) that they play with in the Games tab. Results are rolled by the database, not the browser, so the numbers can be trusted. Use these calls to tie it into your server:

  • Post the leaderboard to Discord or a server website.
  • Announce jackpots as they happen.
  • Reward things that happen in game (kills, events, playtime) with points.
  • Let players trade points for in-game loot: your server tool takes the points with a negative amount, then spawns the item.

api_scores: read the score sheet (any key)

FieldRequiredMeaning
p_keyyesAny key for the server
p_limitnoHow many players, highest points first (default 50, max 500)
{
  "server": { "id": "…", "name": "Badlands PvP" },
  "players": [
    { "username": "someuser", "faction": "Wolves", "faction_tag": "WLF", "points": 4250, "plays": 312,
      "wagered": 15400, "won": 18650, "best_win": 1875, "best_game": "slots", "updated_at": "…" }
  ]
}

api_game_log: jackpots, airdrops and point changes (any key)

Returns up to 100 events after the id you pass, oldest first. Remember the last id you saw and pass it next time.

kindWhen
jackpotA win of 50× the bet or more
big_winA win of 10× the bet or more
airdropA player claimed their free points (every 20 hours)
grantPoints given or taken through api_give_points (note says why)
resetAn admin wiped the score sheet
[ { "id": 118, "kind": "jackpot", "game": "slots", "amount": 7500, "balance": 9120, "note": null,
    "username": "someuser", "created_at": "…" } ]

api_give_points: give or take points (server-wide write keys only)

FieldRequiredMeaning
p_keyyesA server-wide key with write access. Faction keys can't change points.
p_usernameyesThe player's map username. They must have joined the server.
p_amountyesPositive to give, negative to take (up to ±1,000,000). Taking more than they have fails, so nothing is half-done.
p_notenoWhy, shown to the player and in the log, e.g. "Kill: 412m Mosin" or "Bought: NVG"

Returns { "username": "someuser", "points": 3750 }. The player sees the change live.

5. Limits

  • Write keys can only change markers that belong to their faction (faction keys) or Whole server markers (server keys).
  • Changes appear live on everyone's open map.
  • Be reasonable: poll api_map every 30 seconds or slower.
